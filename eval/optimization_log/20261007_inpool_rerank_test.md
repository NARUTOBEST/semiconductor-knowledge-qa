# 2026-10-07 池内 badcase 重排三臂离线测试:英文重排 / 分区重排均无增益

动机:轮次8 后考察"金块在候选池却进不了 top-4"的损失能否靠重排输入
(英文翻译 query / 按块语言分区打分)救回。脚本 `test_inpool4.py`,
数据 `runs/inpool4_result.json`。

## 方法

37 题低 recall 题(recall<0.5),逐题:中文 search 取池(ranked,生产全流水线)
+ LLM 翻译 query 后英文 search 取池,三臂比较 gold 是否进各臂前4:

- **ZH** 现状:中文 query 重排(ranked 序前4)
- **EN** 翻译:英文 query 全流水线(召回+重排都换英文)
- **MIX** 分区:池按块语言分组(英文块取英文分、中文块取中文分),合成排序

## 结果

| 类别 | 题数 | 说明 |
|---|---|---|
| 盲区(金块不在中文池) | 12 | 归召回翻译路,非本测对象(test_translate25 已覆盖) |
| **池内 badcase** | **25** | 三臂命中 top-4:**ZH 13 / EN 13 / MIX 13** |

池内 25 题分解:

- **13 题 ZH 臂就命中**(pos1-4,dev_050/076/105/110/130/143/147/156/157/
  028/039/049 等):离线用题面检索即可进 top-4,评测时的丢失是 agent 实际
  检索词≠题面或运行方差,**不是重排缺陷**(dev_143 结论在此批量复现)。
- **12 题深位(pos 5~132)三臂全不中**(dev_195/030/067/111/141/146/148/
  168/175/042/125):金块语义与 query 本身弱关联(B 类"运算vs原料"错位、
  复合问题稀释等),换重排输入语言救不动。
- 1 换 1:MIX 臂丢 dev_101(pos4)捡回 dev_163(pos6),净零;分区重排
  引入语言判定边界风险,无收益不该上。

## 结论

- **英文 query 重排、分区重排均判无效**,重排侧轮次9 无可做项;
  DUAL_RERANK=0 回退再获佐证。
- 召回侧翻译双路(RRF)仍是唯一有实证的杠杆(盲区 12 题归它管,
  test_translate25 实测 12/23 金块进池)。
- "池内进不了 top4"真实损失远小于账面:25 题里 13 题是口径假象,
  12 题当前手段不可救,留档不再追。
