## 检索外呼三状态熔断(20261009 追加)

engine_api.py 的 translate/rerank 外呼从"逐请求 fail-open"升级为三状态熔断,
复用 agent 侧 tool_circuit.CircuitBreaker 状态机(检索服务独立进程,无干扰):

- **CLOSED**:超时/5xx 指数退避重试(总尝试 RETRIEVAL_BREAKER_RETRY_ATTEMPTS=2
  发,退避 0.5*2^n 封顶 4s);重试耗尽记失败,连续 THRESHOLD=2 次转 OPEN;
  4xx(除 429)按 fatal 不重试不计数(配置错不烧熔断)。
- **OPEN**:外呼快速失败(CircuitOpenError),translate 静默降级英文单路、
  rerank 回退召回序,零延迟损失;冷却 30s。
- **HALF_OPEN**:放 1 个单发探测,成功回 CLOSED、失败回 OPEN 重新计时。
- 进程内 transformers 重排器加载失败仍走 `_reranker_failed` 粘性禁用(永久性
  故障非熔断范畴);/health 新增 breakers 字段观测状态。
- 单测 tests/test_retrieval_breaker.py 13/13(状态机+接线降级,事件握手避免
  并发探测竞态);test_mcp_bridge 8/8、test_engine_fixes+test_circuit_breaker
  35/35 回归通过。**待下次 GPU 开机同步部署**。

## 重排吞吐:跨请求攒批 + 双副本(20261009 追加,方案1+2)

前提:gemma 重排必须保留(中文 query 对英文 chunk 的跨语言精排),vLLM 0.29
载不上(bge-reranker-v2-gemma 是 CausalLM 无打分头,/score 未注册)——吞吐
只能从进程内改造要。瓶颈:RERANK_RECALL_K=96 单请求 96 对,20 并发逐请求
持 RERANK_LOCK 串行 = 1920 对排队,队尾过 MCP 30s 超时。

- **方案1 攒批**(RAG/embed.py `_BatchedReranker`):编码侧"单飞批"同款
  leader-follower——并发请求进队列,leader 睡 RERANK_BATCH_WINDOW_S(50ms)
  收拢后来者合并成一次 compute_score(RERANK_BATCH_MAX_PAIRS=96 封顶,单请求
  超限独自成批),按各请求文档数切分回填。20 并发从 1920 次串行 forward 变
  ~20 个 batch 连打。engine_api/_rerank 与 service /rerank 摘掉全局
  RERANK_LOCK(副本锁内部自管)。
- **方案2 双副本**(RERANK_REPLICAS=2,ret.env 已配):leader 数 = 副本数,
  多 leader 各占空闲副本真并行(try-lock 轮询,全忙退化等第一个,锁序一致
  无死锁)。双副本 ~10.4G + BGE/CLIP ≈ 13G,32G 卡充裕。
- get_reranker() 改返回管线(API 兼容 .rerank);管线是 reranker 实例唯一
  属主,防双份加载烧显存。Reranker 抽出 score_pairs 供攒批器复用。
- 单测 tests/test_rerank_batching.py 9/9(合并/切分/失败整批同享/截断/超限
  独批/双副本并行/全忙退化);test_infer_locks+test_engine_fixes 26/26、
  test_retrieval_breaker 13/13 回归通过。**待下次 GPU 开机随 deploy_gpu.sh
  部署,20u200 复测看队尾延迟与 no_src。**
