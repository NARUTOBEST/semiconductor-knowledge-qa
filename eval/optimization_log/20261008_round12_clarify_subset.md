## 本轮改动(全部部署于 VM backend,GPU 侧 engine_api 已同步)

1. **反问触发加 LLM 门**(`service.py _conflict_objects`):机械冲突信号命中后,
   lite 模型判"问题是否已指明具体对象"——具体问题(如"我想查砷中毒的处理流程")
   不再被相似手册误伤反问;确实没指明才反问。故障 fail-open 不反问。
2. **选项对象化**:选项由 LLM 从 top-4 候选块**内容**提取(设备/机型/物料),
   禁止输出文档文件名;事件附 `option_stems`(对象→文档族映射,评测匹配用)。
3. **scope 强加权全面退役**(用户决策):锁定降级为"本会话已消解、不再反问"
   纯标记;应答轮与粘性轮检索一律正常翻译双路,query 用原问题。轮次12 中途
   曾实现"原问题+对象子查询"双路(均带 scope),被本决策取代后已删。
4. **入口判定改用原问题**(`entry_q`):选项文本(短对象名)按它判会被误路由
   simple(不检索)或再触发澄清。
5. **删除检索域软收窄查询时词面推断路**(`engine_api.py`,`RETRIEVAL_SOURCE_SCOPE`
   废弃;infer_target_stem 仅供冲突预筛豁免用)+ 删 prompt「负证据守门」
   (raglite+react)与「同源纪律」(react)——用户决策"有了反问没必要"。
6. 顺手修 `infer_target_stem` tokenizer 大小写 bug(base 未 lower,大写型号
   token 从未计分,轮次9 护栏意图落空);tests/test_engine_fixes.py 两条过期
   断言修正,16/16 过。

## 结论

1. 反问机制重构成功:触发收敛(37→4)、应答轮 recall 追平直查路径,
   反问不再是 recall 黑洞。
2. 守门 prompt 删除有可测代价(幻觉 5→7、2 道负证据题降级)——若下轮
   全量幻觉率上行超阈值,优先考虑恢复负证据守门(raglite 版)。
3. scope_stem 加权与词面软收窄全部退役后,检索歧义治理只剩反问交互一道;
   dev_069 类"锁对文档但块没中"需靠 K/邻块扩展另治。
